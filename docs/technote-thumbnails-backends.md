# Technical note: the backends of the thumbnails

The thumbnail of a book is the first page of its PDF file, as a JPEG image
of 300 pixels wide, in the cache directory (`<sha1>.jpg`). Code:
`srcs/cache.py`, `Cache.__pdf2jpeg()`. Three backends make the image; by
default they are tried in this order until one succeeds, and the book page
(or `python -m srcs.cli thumbnails regenerate --backend`) can choose one.

## Ghostscript in every case

ImageMagick has no PDF renderer of its own: for a PDF file, it runs
Ghostscript (`gs` delegate). So each of the three backends ends up in a
single call of `gs`; what differs is what `gs` is given, and its options.
Then, in every case, the image is reduced to 300 pixels wide by ImageMagick
(`__thumb_resize_small()`, JPEG to JPEG).

The `gs` commands below were captured (`strace -e trace=execve`) with
ImageMagick 6.9.12 and Ghostscript 10.02.

## Comparison

|                       | `pypdf-wand`                     | `wand`                          | `ghostscript`                   |
|-----------------------|----------------------------------|---------------------------------|---------------------------------|
| Given to `gs`         | a 1-page PDF, rewritten by pypdf | the PDF file, page 1 only       | the PDF file, page 1 only       |
| Run by                | ImageMagick (wand)               | ImageMagick (wand)              | the code (`subprocess`)         |
| Resolution            | 72 dpi                           | 72 dpi                          | 150 dpi, halved while the image is over 2 MB |
| Page box              | CropBox (`-dUseCropBox`)         | CropBox                         | MediaBox                        |
| `gs` device           | `pngalpha`, flattened on white   | `pngalpha`, flattened on white  | `jpeg`                          |
| ImageMagick PDF policy | required                        | required                        | not used                        |

The `gs` command run by ImageMagick (both wand backends; `wand` adds
`-dFirstPage=1 -dLastPage=1`):

```
gs -sstdout=%stderr -dQUIET -dSAFER -dBATCH -dNOPAUSE -dNOPROMPT
   -dMaxBitmap=500000000 -dAlignToPixels=0 -dGridFitTT=2
   -sDEVICE=pngalpha -dTextAlphaBits=4 -dGraphicsAlphaBits=4 -r72x72
   -dPrinted=false -dUseCropBox -sOutputFile=... -f<pdf>
```

The `gs` command of the Ghostscript backend:

```
gs -q -dSAFER -sDEVICE=jpeg -o <jpg> -dFirstPage=1 -dLastPage=1 -dJPEGQ=92 -r150 <pdf>
```

## What each one brings

- **`pypdf-wand` and `wand`** are the same rendering; the only difference
  is the rewrite of the first page by pypdf. It helps:
  - a PDF file whose structure Ghostscript can not read, but pypdf, more
    tolerant, can (broken cross-reference table, damaged objects elsewhere
    in the file);
  - a large PDF file: `gs` reads a 1-page file instead of the whole
    structure.

  pypdf fails on other files (password, unusual structures): `wand` is
  then tried on the original file.
- **`ghostscript`**:
  - the only one which works when the security policy of ImageMagick
    forbids PDF files, the default of several distributions (see "Policy
    tuning" in the README);
  - 150 dpi: at 72 dpi, a page less than 300 points wide gives an image of
    less than 300 pixels, which the reduction to 300 pixels enlarges, thus
    blurs;
  - the MediaBox: on a PDF file made for printing, the bleed or the crop
    marks may show.

## Colours

The page is read in RGB by the wand backends (`colorspace="srgb"`):
otherwise ImageMagick renders a PDF file with CMYK colours (a printed
cover) in CMYK, saved as a CMYK JPEG without colour profile, which the
browsers convert naively, with wrong colours (a teal becomes a fluorescent
green). Read in RGB, the conversion is done by Ghostscript with its colour
profiles, as for the Ghostscript backend. The thumbnails made in CMYK by
older versions are found and regenerated by `python -m srcs.cli thumbnails
check` and `thumbnails regenerate --cmyk` (see the README).

## Possible simplification

Not done, kept for reference: call Ghostscript directly in every case,
with `-dUseCropBox`, and keep the rewrite by pypdf only as a fallback for
the damaged files. ImageMagick would only reduce the image (or not at all,
`gs` rendering at the right size): one layer less, no dependency on the
ImageMagick policy, and no difference of resolution (72 / 150 dpi).
